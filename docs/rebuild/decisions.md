### Decisions

- D1 — Target repo is a fresh repository at `/Users/ericguei/Documents/caos-databricks`, not `caos-workbench`. Alternatives: reuse `caos-workbench` (a working clone of the same legacy). Reason: the meta-prompt describes a one-shot rebuild from a read-only snapshot; a clean tree keeps gate baselines honest and the legacy history out of the way.
- D2 — Python pin is `>=3.13,<3.14` (`requires-python`) with `.python-version = 3.13`. Alternatives: 3.14 (legacy). Reason: the fixed requirement is ≥3.13; Databricks Apps honours `requires-python` (R8) and needs an upper bound (R9); 3.13 has the widest wheel coverage for the Databricks stack (`mlflow`, `databricks-sdk`, `psycopg[binary]`), which matters under the wheels-only rule. Ruff `target-version` and mypy `python_version` move to 3.13 with no rule removed. Decimal semantics are identical across 3.13/3.14, so parity goldens produced by the 3.14 legacy remain valid.
- D3 — Frontend is KEEP (copied as-is with all seven of its gates). Alternatives: drop for a v1 API-only app; rebuild in AppKit. Reason: the platform move changes provider, persistence and runtime, not the workspace; the wire contract (`frontend/src/wire/v1/schema.json`) already binds the API shape, and Databricks Apps serve a static export from FastAPI exactly as legacy `server/api/site.py` does. Node 24 and Playwright are present locally.
- D4 — Deploy V stays a vendored, byte-verified bundle at `vendor/deploy-v/` and is never edited (legacy invariant 4). ICM stage folders do not copy its files; each stage contract's Inputs table names the bundle files by path and the runtime loads them through the verified `Bundle` seam. Alternatives: refactor the 25 SKILL.md files into stage `references/`. Reason: copies would break the integrity manifest and `verify_package.py`, and the legacy qualification verdicts bind the bundle build id. "Drop Claude Code frontmatter" therefore applies to the dropped legacy dev skills and the external corpus, not to the bundle.
- D5 — Architecture split (meta-prompt default, confirmed by R17): LangGraph owns execution, state, interrupts and persistence; ICM owns stage folders (`icm/stages/<deploy-v-slug>/`), each with `CONTEXT.md` (contract), `prompt.md` (host prompt template) and `references/` (host-owned files only, e.g. CP-CF). Root `CLAUDE.md` is Layer 0; `icm/CONTEXT.md` is Layer 1 (module index + the rule that the pinned route, not folder numbering, is execution order, per the Deploy V README). Legacy root `CONTEXT.md` (vocabulary) keeps its name because `scripts/check_vocabulary.py` reads it.
- D6 — Checkpointer vs legacy invariant 6 ("no checkpointer, recovery is recomputation"). Decision: use the Lakebase `CheckpointSaver` for graph position, thread identity and interrupts (fixed requirement), but the accepted-attempt ledger remains the only truth for node completion: on resume, `node_states` over the store decides what runs, and a node COMPLETE in the ledger is skipped regardless of checkpoint contents. Reason: keeps exactly-once and one-charge-per-node while satisfying the fixed requirement.
- D7 — Model factory: `caos/models.py::chat_model(...)` returns `ChatDatabricks(endpoint=CAOS_MODEL_ENDPOINT)`; default endpoint `databricks-claude-opus-5`; tests inject `tests/openrouter_adapter.py` (LangChain `ChatOpenAI` against `https://openrouter.ai/api/v1`, model `anthropic/claude-opus-5-20260723`, key from `OPENROUTER_API_KEY`) through a fixture; `langchain-openai` lives in the `dev` group only. Alternatives: Sonnet 5 default. Reason: the legacy qualification runs used a frontier model at high effort with 65,536-token completions; Opus 5 is the same tier and the same family on both sides; endpoint is env-configurable so `GATEWAY_ENDPOINTS` can override without code.
- D8 — Charge accounting changes from OpenRouter `usage.cost` to `usage_metadata` tokens × the dated `CAOS_MODEL_PRICE` (Decimal). Reason: Databricks responses carry tokens, not money. Reservation arithmetic (`priced_request`, `worst_case`) is unchanged and parity-tested; the charge path gets contract tests. Qualification identity becomes `databricks/<endpoint>/<effort-or-none>/65536`.
- D9 — Blob store backend: Unity Catalog Volume via the SDK Files API (`w.files.upload/download`, path `/Volumes/<catalog>/<schema>/caos_blobs/<sha256[:2]>/<sha256>`), filesystem backend kept for tests and local dev.
